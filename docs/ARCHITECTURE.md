# Архитектура

Коротко: **матч** считает бой, **режим** задаёт правила, **контроллеры** управляют бойцами, **движок** всё это показывает.

```
            ┌──────────── контроллеры ────────────┐
 джойстик → │ local   bot (bot.js)   remote (сеть) │ → команда { moveX, moveZ, aimDir, attack, ult }
            └──────────────────────────────────────┘
                                │
                                ▼
 режим (src/modes/*) ──► МАТЧ (src/game/match.js) ──► события: урон, смерть, звук, конец матча
   кто на арене,          бойцы, приёмы героев,                    │
   счёт, победа           снаряды, столкновения                    ▼
                                                   ДВИЖОК (src/game/engine.js): 3D, камера,
                                                   прицел, полоски ХП, звук → HUD в React (src/ui)
```

## Матч — `src/game/match.js`
- Хранит бойцов, снаряды, опасные зоны, время.
- `match.step(dt, controllers)` — один шаг боя: команды → движение и приёмы → столкновения → снаряды → смерти и возрождения → правила режима.
- Ничего не рисует и не играет. Всё, что должен увидеть или услышать игрок, кладёт в `match.events`: `damage`, `death`, `respawn`, `sfx`, `say`, `finish`.
- Конец матча — `match.finish({ winners, places, reason })`.

## Режимы — `src/modes/<id>.js`
Режим — объект с `setup`, `update`, `onDeath`, `hud`. Интерфейс описан в `src/modes/index.js`. Каждый файл — отдельный режим, они собираются сами и появляются в меню.

## Контроллеры — `src/game/controllers.js`
Кто управляет бойцом. У всех один метод: `command(dt, world)` возвращает команду кадра.
- `local` — джойстик и кнопки этого устройства.
- `bot` — бот (`src/game/bot.js`).
- `remote` — **ещё нет**, место под сетевого игрока.

Команда — простой объект без ссылок, её можно переслать как JSON.

## Как будет устроен мультиплеер (план, пока не сделано)
1. **Хост** — телефон одного из игроков или сервер — запускает `createMatch` как сейчас.
2. Для бойцов других игроков режим выдаёт `control: 'remote'`, а движок создаёт для них контроллер, который возвращает последнюю пришедшую по сети команду.
3. Клиенты шлют хосту свои команды — те же объекты, что собирает `createLocalController`. Хост каждый кадр рассылает события из `match.events` и позиции, ХП и статусы бойцов.
4. Клиент показывает присланное состояние тем же движком. Матч у себя он не считает, только рисует и сглаживает.
5. Транспорт — WebSocket или WebRTC. Для Telegram Mini App подойдёт WebSocket через свой сервер или Supabase Realtime.

Что для этого уже готово:
- управление отделено от боя;
- правила — в режимах;
- всё видимое и слышимое идёт через события;
- команды сериализуются.
