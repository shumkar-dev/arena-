# Архитектура

Коротко: **матч** считает бой, **режим** задаёт правила, **контроллеры** управляют бойцами, **движок** всё это показывает.

```
            ┌──────────── контроллеры ────────────┐
 джойстик → │ local   bot (bot.js)   remote (сеть) │ → команда { moveX, moveZ, aimDir, attack, ult }
            └──────────────────────────────────────┘
                                │
                                ▼
 режим (src/modes/*) ──► МАТЧ (src/game/match.js) ──► события: урон, смерть, звук, конец матча
   кто на арене,          бойцы, приёмы героев,                    │
   счёт, победа           снаряды, столкновения                    ▼
                                                   ДВИЖОК (src/game/engine.js): 3D, камера,
                                                   прицел, полоски ХП, звук → HUD в React (src/ui)
```

## Матч — `src/game/match.js`
- Хранит бойцов, снаряды, опасные зоны, время.
- `match.step(dt, controllers)` — один шаг боя: команды → движение и приёмы → столкновения → снаряды → смерти и возрождения → правила режима.
- Ничего не рисует и не играет. Всё, что должен увидеть или услышать игрок, кладёт в `match.events`: `damage`, `death`, `respawn`, `sfx`, `say`, `finish`.
- Конец матча — `match.finish({ winners, places, reason })`.

## Режимы — `src/modes/<id>.js`
Режим — объект с `setup`, `update`, `onDeath`, `hud`. Интерфейс описан в `src/modes/index.js`. Каждый файл — отдельный режим, они собираются сами и появляются в меню.

## Контроллеры — `src/game/controllers.js`
Кто управляет бойцом. У всех один метод: `command(dt, world)` возвращает команду кадра.
- `local` — джойстик и кнопки этого устройства.
- `bot` — бот (`src/game/bot.js`).
- `remote` — игрок по сети: последняя присланная команда движения и очередь ударов и ульт.

Команда — простой объект без ссылок, её можно переслать как JSON.

## Мультиплеер — комнаты по коду (1 на 1, 2 на 2, каждый сам за себя)
```
 телефоны ──команды──►  СЕРВЕР (server/, Node + ws)  ──снимки 30/с──► телефоны
                        комнаты → createMatch + режим (те же src/modes/*), боты на свободных местах
```
- **Комната.** Создатель получает код из 4 символов, друзья входят по коду (до 4 человек). Режим создатель выбирает уже в лобби и может менять до старта: места пересчитываются под режим, игроки пересаживаются (`reseat`); если третий входит в комнату 1 на 1 — она сама становится 2 на 2. Каждый может сменить героя в лобби, в том числе между боями. В лобби видны места с героями (в 2 на 2 — по командам, можно перейти в другую), у создателя — «Старт». Пустые места занимают боты с никами из `BOT_NAMES`, их сила — по средним уткам людей в комнате (`botSkill`). После боя комната возвращается в лобби. Кто вышел посреди боя — за его героя дальше играет бот.
- **Сервер авторитетный** (`server/index.js`). Он запускает тот же `createMatch`, те же режимы и приёмы героев, что игра: сборка `npm run build:server` кладёт `src/` и three.js в один файл. Сцена — пустая группа, эффекты — пустышки. Карта — общий объект процесса, поэтому перед шагом каждой комнаты сервер ставит её карту (`setMap`).
- **Режимы с готовым составом.** `setup(match, opts)` каждого режима принимает `opts.roster` — `[{ heroId, name, control }]` по местам — и `opts.you` (своё место; на сервере — `null`). Без него — обычная игра: ты на месте 0, остальные — боты (`rosterOf` в `src/modes/common.js`). У режима есть `slots` (сколько мест) и `teamOf(i)` (команда места). `createOnlineMode` (`src/net/protocol.js`) собирает сетевой режим из обычного: на сервере у людей `control: 'remote'`, у ботов — `'bot'`; на устройстве все, кроме тебя, — `'remote'`.
- **Что в снимке и сколько трафика.** Снимок — 15 раз в секунду (бой считается 30), компактный массив `[1, номер, время мс, ack, изменения, события, extra?]`. Боец упакован в целые числа (`packFighter`: координаты в сантиметрах, углы в сотых радиана, статусы строкой), и каждому игроку идут только поля, изменившиеся с его прошлого снимка (`diffFighter`) — стоящие бойцы, бутылки и мёртвые не передаются вовсе. Счёт `sc` и предметы `pk` — только при изменении. Сверху — сжатие WebSocket (permessage-deflate). Итого вниз ~0,6 КБ/с в 1 на 1 и ~1,7 КБ/с в «сам за себя» (было 7 и 24 КБ/с). Команды игрока — при изменении джойстика (до 20 раз в секунду, не реже 10), ~0,5 КБ/с вверх.
- **Затор.** В каждой команде игрок сообщает номер последнего полученного снимка (`k`). Если он отстал больше чем на 20 снимков или у сокета скопилось больше 24 КБ, сервер пропускает снимки этому игроку, а не копит очередь; события копятся и уходят со следующим снимком. На устройстве после затора рисуем по самому свежему снимку, старые пропускаем. Пинг в бою — медиана пяти замеров времени туда-обратно (сообщение идёт в общей очереди со снимками, так что забитый канал видно).
- **Игра** (`src/net/client.js` — соединение, `src/net/sync.js` — синхронизация). Движок считает у себя копию матча только для картинки: анимации, снаряды, эффекты, звуки, походка прохожих.
  - ХП, смерти, возрождения, статусы, захват, счёт и предметы берутся из снимков; урон на устройстве — только вспышка, цифры урона приходят с сервера. Подбирает предметы и решает, кто выбыл, только сервер.
  - **Остальные** (игроки, боты, прохожие) рисуются на 100 мс в прошлом, между двумя снимками (интерполяция); удары и ульты героев приходят событиями и проигрываются их же приёмами.
  - **Свой боец** двигается сразу по джойстику (предсказание). Каждая команда пронумерована; сервер в снимке сообщает номер последней применённой (`ack`) и позицию, игра сравнивает её со своим предсказанием для того же номера и плавно убирает разницу (прыжком — если больше 2,5 м).
  - Кто начинает на северной половине, видит арену с другой стороны: камера и оси джойстика перевёрнуты (`flip`).
- **Итог и утки.** Конец матча решает сервер: в `end` — победители и для каждого героя место, победа, первое место по убийствам и утки по правилам GDD (`matchParticipants` + `rewardFor`). Свои утки каждый телефон записывает сам; утки ботов — только телефон создателя комнаты, чтобы боту не начислили дважды.
- Развёртывание — `server/README.md`.

Что дальше можно добавить тем же путём: подбор случайных соперников без кода, смена героя прямо в лобби.

## Обновления игры
- **Версия сборки** — коммит (`GITHUB_SHA` на Actions) или время сборки. Зашивается в код (`__APP_VERSION__`, `vite.config.js`) и кладётся на сайт в `version.json`.
- **Проверка** (`src/ui/update.js`): при запуске, раз в 5 минут и когда игру снова открывают из фона. Новее — в меню и на экране итога боя появляется «Доступно обновление»; во время боя плашки нет. «Обновить» перезагружает страницу по адресу с меткой `?u=…`, поэтому она точно приходит с сайта, а не из кэша телефона.
- **Service worker** (`public/sw.js`) регистрируется как `sw.js?v=<версия>`: у каждой версии свой кэш, старые удаляются. Страница и `version.json` всегда берутся из сети мимо HTTP-кэша, без сети — из кэша.
- **Версия протокола мультиплеера** — `PROTOCOL` в `src/net/protocol.js`. Её нужно увеличить, если игра и сервер перестают понимать друг друга (формат снимков, сообщения). Сервер называет свою версию в `hello` сразу после подключения, игра — в `create`/`join`. Не совпало: игра старее — «Обнови игру» с кнопкой; сервер старее (или не прислал `hello`) — «Сервер обновляется»; старой игре сервер отвечает ошибкой с текстом «Обнови игру».
